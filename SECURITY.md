# Security policy

Sealed is experimental and has not been independently audited. Please do not include
private messages, live keys, unlock keys, or other secrets in a report.

Until a dedicated private reporting channel exists, open a minimal repository issue
that asks maintainers to establish confidential contact without revealing exploit
details. For an immediate local fork, preserve evidence, stop using affected keys,
and do not assume deleting a file erases SSD or filesystem copies.

Security reports should identify the affected commit/version, platform, expected
security invariant, minimal non-secret reproduction, and whether public disclosure is
already necessary. There is no promise of a server, account, recovery key, automatic
update, or remotely delivered fix. Users must independently verify and install any
future patched source or binary.

The maintainers and AI-generated code are not trust roots. Independent review of the
protocol, implementation, vendored dependencies, vectors, and release artifacts is
part of the security model.
